Set up the tunnel tray app

Run a Cloudflare Tunnel hidden on a Windows PC, with a tray icon for its status, and let a Cloudflare Worker reach a local service through it.

Steps
  1. Requirements
  2. Get the files
  3. Download cloudflared
  4. Create .env
  5. Log in to wrangler
  6. Create the tunnel and VPC service
  7. Add the tunnel token
  8. Build the tray app
  9. Run it and start at login
  10. Connect your Worker
  11. Check it works
  12. Troubleshooting

1Requirements

  • Windows 10 or 11. The build uses the .NET Framework compiler and Windows PowerShell 5.1, which ship with Windows.
  • Node.js 18 or newer, for npx wrangler. You only need it during setup.
  • A Cloudflare account, with access to Zero Trust (the free plan is enough).
  • The local service the Worker should reach, for example a web app on http://127.0.0.1:8050.

Run every command below in PowerShell, from the project folder.

If PowerShell refuses to run .ps1 scripts, allow local scripts for your user once:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

2Get the files

Clone the repository, or copy the folder, to a permanent location. The tray app runs from that folder, and Start at login stores the path.

git clone <repo-url>
cd fcd

Every command below runs from this folder and uses paths relative to it.

3Download cloudflared

cloudflared.exe is Cloudflare's tunnel client. It isn't in git because it's about 55 MB, so download it into the project folder:

Invoke-WebRequest https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe -OutFile cloudflared.exe
.\cloudflared.exe --version

To update it later, exit the tray app and run the same download again.

4Create .env

All settings live in .env. It's git-ignored because it holds the tunnel token. Start from the template:

Copy-Item .env.example .env
notepad .env

For now, fill in only the values in bold. The setup script fills in the IDs, and the token comes in step 7.

KeyWhat it is
TUNNEL_TOKENThe tunnel's secret connector token. Added in step 7.
CLOUDFLARE_ACCOUNT_IDYour account ID. Optional: the setup script fills it in from your wrangler login.
TUNNEL_NAMEName for the tunnel, e.g. my-tunnel.
TUNNEL_IDFilled in by the setup script. If the tunnel already exists, paste its ID here and the script will skip creating it.
VPC_SERVICE_NAMEName for the Workers VPC service, e.g. tasks.
VPC_SERVICE_HOSTNAMEWhere the local service listens, as seen from this PC. Default 127.0.0.1. Use it rather than localhost, which can resolve to IPv6 (::1) first.
VPC_SERVICE_HTTP_PORTThe local service's port, e.g. 8050.
VPC_SERVICE_IDFilled in by the setup script.
WORKER_URLThe Worker that uses the service. For reference only.
APP_NAMEName shown in the tray tooltip and notifications.
APP_PUBLISHERPublisher stamped into cloudflared-tray.exe, shown in Task Manager and file properties. Default Cloudflared Tray. Rebuild (step 8) after changing it.
TUNNEL_PROTOCOLhttp2 (works through most firewalls) or quic.
METRICS_PORTLocal port where cloudflared reports its status. Default 20251.

5Log in to wrangler

Wrangler is Cloudflare's command-line tool. This opens a browser so you can approve access to your account:

npx wrangler login
npx wrangler whoami

6Create the tunnel and VPC service

.\cloudflare\setup.ps1

The script:

  1. checks your wrangler login and records your account ID;
  2. creates the tunnel TUNNEL_NAME, or reuses it if it already exists, and writes TUNNEL_ID to .env;
  3. creates a Workers VPC service that points at http://VPC_SERVICE_HOSTNAME:VPC_SERVICE_HTTP_PORT through that tunnel, and writes VPC_SERVICE_ID to .env.

It's safe to run again: any step whose ID is already in .env is skipped. The commands it runs are:

npx wrangler tunnel create <TUNNEL_NAME>
npx wrangler vpc service create <VPC_SERVICE_NAME> --type http --tunnel-id <TUNNEL_ID> --hostname <HOST> --http-port <PORT>

wrangler tunnel is marked experimental. If it fails, create the tunnel in the dashboard instead (Zero Trust → Networks → Tunnels → Create a tunnel → Cloudflared), paste its ID into TUNNEL_ID, and run the script again.

7Add the tunnel token

The token lets cloudflared run as this tunnel. To get it:

  1. Open Cloudflare Zero Trust → Networks → Tunnels.
  2. Open your tunnel → Configure.
  3. Under the install commands, copy the long string after --token.
  4. Paste it into .env as TUNNEL_TOKEN=....

Treat the token like a password: anyone who has it can run your tunnel. Keep it only in .env, and never commit it. If it leaks, rotate it from the tunnel's page in the dashboard.

8Build the tray app

.\build-tray.ps1

This compiles cloudflared-tray.exe, a small host that runs cloudflared-tray.ps1 with no console window and uses cloudflared-tray.ico as its icon. You only need to rebuild after changing APP_PUBLISHER, the exe's name or the icon. Other changes to .env or the .ps1 just need a restart of the tray app. If the tray app is already running, the script stops it for the build and starts it again afterwards.

9Run it and start at login

.\cloudflared-tray.exe
  • A cloud icon appears in the system tray: white when connected, faded gray while connecting or stopped.
  • Right-click it → tick Start at login.
  • The menu also has Stop/Start, Restart, Open log, and Open Cloudflare dashboard.

Windows may put new icons in the ^ overflow menu. To keep it visible, drag it onto the taskbar, or turn it on under Settings → Personalization → Taskbar → Other system tray icons.

10Connect your Worker

In the Worker's project, bind the VPC service in wrangler.jsonc, using VPC_SERVICE_ID from .env:

{
  "vpc_services": [
    { "binding": "TASKS", "service_id": "<VPC_SERVICE_ID>" }
  ]
}

Then call the local service through the binding:

const res = await env.TASKS.fetch("http://localhost/api/health");

Requests go through the tunnel to the hostname and port set on the VPC service. Deploy with npx wrangler deploy.

11Check it works

# Local: cloudflared is connected (expect status 200)
Invoke-RestMethod http://127.0.0.1:20251/ready

# Cloudflare: tunnel and VPC service as Cloudflare sees them
.\cloudflare\status.ps1

The tunnel should show as Healthy under Zero Trust → Networks → Tunnels.

12Troubleshooting

“.env not found” or “TUNNEL_TOKEN is empty”
Steps 4 and 7. .env must be in the same folder as cloudflared-tray.exe.
Tray icon stays gray
Right-click → Open log and look for errors near the end. A bad token shows as an authentication error. If http2 is blocked, try TUNNEL_PROTOCOL=quic, or the other way round.
No tray icon at all
It's probably in the ^ overflow menu (see step 9). Check that it's running with Get-Process cloudflared-tray.
build-tray.ps1 fails with “file in use”
The script stops this folder's tray app before building, so this means another program has the exe open, for example its Properties window or a security scan. Close it and build again.
“Not logged in” from the setup script
Run npx wrangler login again. The login expires after a while.
The Worker gets errors from the binding
Check that the local service answers at http://VPC_SERVICE_HOSTNAME:VPC_SERVICE_HTTP_PORT on this PC, that the tray icon is white, and that service_id matches VPC_SERVICE_ID.
